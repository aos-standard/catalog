@maximusrufus on offering the vectors as one conformance suite: a data point on whether results stay comparable as the profile moves.

The reader this catalog froze for profile 1.4.2 on 2026-10-27 (v142.1, 90/90 at `cb7e8f1`), run unchanged against `v1.4.7` (`6f7a075`): **108/115**.

- Vectors 01-90 are byte-identical between `cb7e8f1` and `v1.4.7`. All 25 changes since are additions, and the reader agrees with all 90 again.
- Each of the seven it misses is a rule added or made explicit after 1.4.2: 95, 105 and 107 (1.4.3, the stated-time and genTime forms), 110 and 112 (1.4.5, `relying_party_keys`), 114 and 115 (1.4.7, the point rule for the producer's key).

So "agrees with N of 115 at tag X" is a statement other implementations can compare, and the misses name the profile versions a reader has not followed. That holds while the suite stays append-only, as it has from 1.4.2 to 1.4.7. If a vector ever has to change meaning, a new number instead of an edit would keep it.

This is not a claim of conformance to 1.4.7. No reader for 1.4.7 was written here. Record: [`ADDENDUM-v147-unchanged.md`](https://github.com/aos-standard/catalog/blob/00edd7e/docs/runs/work-acceptance-record-cold/ADDENDUM-v147-unchanged.md). CC0.
