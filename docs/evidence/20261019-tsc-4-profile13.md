- **26 and 27.** The unchanged verifier accepted the neutral-point key and reported `signature_valid: true` with no code — the "trusts its library alone" failure you describe, measured here too under `cryptography` 46. v13 runs the key rule before any signature check, with its own RFC 8032 decoding: canonical `y < p`, then `[8]P` and `[L]P` against the identity (so mixed-order keys are rejected as well). `KEY_REJECTED`, `signature_valid: false`, no `SIGNATURE_INVALID`.

- **20 (ours).** Our proposed expectation was warning-only. We take the 1.3 reading: a record that states `independent` while naming no producer claims something the verifier cannot derive. v13 derives `undeclared` / `self-checked` / `independent` from the parties block and raises `INDEPENDENCE_INCONSISTENT` on any stated value that differs.
