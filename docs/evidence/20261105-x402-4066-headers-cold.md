An independent run of these vectors, from outside the project. I wrote a decoder from `http.md` and the Scope section of `vectors/README.md` only (no SDK code and not `headerVectors.test.ts`), froze it, and then scored it once against `http_headers.json` at `c3e23c9`:

- **16/16 cases** (30/30 case × header runs), with no mismatches.

Notes and expectations were sealed until the freeze. The ids and values were seen. Record, decoder, runs and pins: [`docs/runs/x402-http-headers-cold/`](https://github.com/aos-standard/catalog/tree/c3db1ad/docs/runs/x402-http-headers-cold). CC0.

So a third implementation can read the shared file without any SDK in hand, which is the point of the PR. I then changed one decoding rule at a time and reran the cases. Two observations may help before the file is used by other SDKs.

**1. The strict alphabet is pinned by one case.** A decoder that drops characters outside the alphabet, as Python's `b64decode` default and Node's `Buffer.from(s, 'base64')` do, fails only `alphabet-space`. `alphabet-percent-encoded-pad` pins "do not percent-decode". A lenient decoder rejects it too, because dropping `%` leaves `3D` as data.

**2. Seven rules are reached by no case and are not on the README's "Not covered" list.** A decoder that accepts each of these still passes 16/16:

1. `==` appended to a value that already fills its last quantum
2. `=` inside the value (two encodings concatenated)
3. CR LF line breaks, MIME-style (RFC 4648 3.1)
4. non-zero pad bits in the last character (RFC 4648 3.5 lets a decoder reject them, and the spec does not say whether it must)
5. the JSON in UTF-16 with a BOM (`json.loads(bytes)` in Python detects the encoding)
6. `NaN` as a member value
7. data after the JSON value

[`runs/candidates_c3e23c9.json`](https://github.com/aos-standard/catalog/blob/c3db1ad/docs/runs/x402-http-headers-cold/runs/candidates_c3e23c9.json) has one case for each, in this file's layout, each one change from an `http.md` example. Six expect `reject`. The pad-bits case has no expectation, since that one is a choice for the spec. The expectations are my reading, so take any that are useful, or none. They can be copied as they are.
