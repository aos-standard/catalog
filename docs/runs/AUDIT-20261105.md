# Audit of this directory against METHOD.md, 2026-11-05

`METHOD.md` promises four practices for every run here. On 2026-11-05 we checked all 24 run directories with a
script that only reads (`runs_method_audit.py`, five checks per run). The script found places where the practice
was narrower than the promise. This page records what it found and what we added. No existing file of any run was
changed. Everything below was added beside the existing files.

## 1. Checksums: added where missing

`METHOD.md` §3 says every file of a run is listed in `SHA256SUMS`.

- **Eight runs had no checksum file at all:** `acceptance-record-cold-27`, `ap2-evidence-pack-cold`,
  `jcs-number-vectors`, `ledger-timestamps`, `priorseal-exact-call-matrix-v1`,
  `priorseal-exact-call-matrix-v1.0.1-cold-run`, `priorseal-g9-g11-seams-2ff89d8`, `x402-delivery-receipt-cold`.
- **Four runs had files that no checksum file listed:** `acp-dispute-cold` (`ADDENDUM-089d8f9.md`),
  `anchor-pointer-draft1.1` (`ADDENDUM-2d721cb.md`), `aps-lease-revocation-axes-cold` (`CLARIFICATION-86e5e7a.md`), and
  `work-acceptance-record-cold`. In that last run, only the two latest versions (profile 1.4.2 and the cb7e8f1
  correction) had checksum files. 102 earlier files were not listed.

**What was added.** Each of these twelve runs now has `SHA256SUMS-20261105`. It lists each file that no earlier
checksum file listed, with its sha256 on 2026-11-05.

**Whether these are the published bytes.** For every listed file but three, git shows a single commit, so its
bytes on 2026-11-05 are its bytes as first published. The three exceptions are the files of §2. For those, the listed
bytes are their latest version, and §2 says where the earlier bytes are. `ledger-timestamps/README.md` is left out on purpose. It is an
index that gains a row each month, so it is not a frozen file.

## 2. Three files in `work-acceptance-record-cold` were edited in place

On 2026-10-23, the v141.2 and v141.3 fixes were written into `tsa_check_141.py` and `war_cold_verifier_v141.py`
instead of into new files. `FROZEN_V141.txt` was extended in the same commit, which also edited that file in place.
The hash of every version stayed in `FROZEN_V141.txt`. The v141.1 bytes, however, were left only in the git history
(commit `8c210d1`). This broke the rule that every reader version is kept.

**What was added.** `work-acceptance-record-cold/superseded-v141.1/` now holds the v141.1 `tsa_check_141.py`,
`war_cold_verifier_v141.py` and `run_vectors_v141.py`, taken from `8c210d1`. Their sha256 match the `v141.1` lines of
`FROZEN_V141.txt`:

| `tsa_check_141.py` | `f39cba9f…` |
| `war_cold_verifier_v141.py` | `535cbcf6…` |

The first v141 `tsa_check_141.py` (`8296e9ed…`) was never published as a file. Only its hash is recorded.

- **A link to `main`.** One link in `ledger-timestamps/checks-2026-10-23/CONDUCT_at_109a30d.jsonl` points to `main`.
  It is inside a copied conduct-ledger row (VCL-0021), which records the URL as it was posted on 2026-09-29. A copy
  is not edited.

Each run above remains what its own page says it is, and no more.
