# Addendum to RUN-2026-10-15.md — the corrected 50-vector pin `6e487f0`

On 2026-10-15 (UTC 04:53) TKCollective reported, from their own run of the
upstream checker with tanilo-receipt-verify's Ed25519 layer substituted in, that
`acc-mixed-order-key-accepted-by-both-equations` only held for verifiers that
reduce `k` modulo `L`; RFC 8032 §5.1.7 uses the full SHA-512 digest. The
maintainer confirmed it was the builder's fault (`k mod L`) and rebuilt that one
vector at `6e487f0` so it holds under both conventions. Only that vector's `R`
and `S` changed; its expected result is still `key_unresolved`; the other 49
are byte-identical to `9d4cf2c`.

No reader's result moved. For the rebuilt vector: v3 still returns
`key_unresolved` from the `[L]A` check before any signature arithmetic, so the
change to `R`/`S` cannot reach it; v2 still verifies it (v2 has no `[L]A` test,
and `cryptography` accepts the new signature as it accepted the old); v1 as v2.

What this run did not do: it did not detect the builder's convention error.
v3 passed the old vector because its `[L]A` check fires before verification,
which is the point of sentence 9 but also means v3 never exercised the
signature that was wrong. TKCollective found it by substituting a verifier that
does not reduce `k`; a reader that only checks the subgroup cannot. Recorded so
the 50/50 is not read as covering more than it does.
